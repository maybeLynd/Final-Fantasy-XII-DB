# Ordered queue outputs and nullable primitive

Producer-valid retained method A; independent acceptance and canonical incorporation pending. Original `00309C00` and its `00348330` bridge are already published. No new capture, native/emulated call or game session was needed.

The primitive reads queue DWORD `022C2178`. If it equals −1, it returns DWORD zero without writing any output or resetting the queue. Otherwise it conditionally writes that action value to non-null RDX, then conditionally loads unit DWORD `022C218C` and writes it to non-null RCX. It finally resets the queue to −1 and returns DWORD one. Therefore **both output pointers may be null at the primitive boundary and a pending value is still consumed**. Eight logical branch partitions establish this; they are not eight native calls.

The two output fields are written in order, not simultaneously. For valid, non-null output ranges disjoint from the source/reset globals, the later unit write overwrites any intersection with the earlier action write. If both pointers address the same four bytes, both views end with the unit DWORD. Byte-range-disjoint outputs preserve both values independently of their contents. A shared value, or an overlapping byte that happens to match, can hide that overlap in a sample; absence of a visible difference would not prove nonaliasing.

`result-01.json` gives the byte formula and nine illustrative calculations at pointer differences −4 through +4. These are arithmetic countermodels under explicit valid-address/disjoint-global premises, not original executions or naturally occurring script references. The unit global is loaded **after** the action write. An output aliasing that global could change the later load; an output aliasing the reset global could be overwritten by the final reset. Those aliases are outside the unchanged-source formula, not silently treated as stable inputs.

The full script bridge has stricter preconditions than this nullable primitive. After `00309C00` returns normally, `003483A9` and `003483B1` unconditionally read the two destinations through RBX and RSI for debug state. The code takes those reads even if the primitive returned zero. Thus null guards in the primitive do **not** prove a safe whole bridge call with invalid destinations. No actual null reference or exception/fault was observed.

This qualifies OV42's intervening native-output/unchanged-transfer premise: a proper representation alone does not guarantee that two out references preserve their respective values.
