# Rig owner rebinding preconditions

Method A answers an exact implementation question: do the separate link-only
and full-reset rebinders safely bypass a missing derived owner, and do their
index producers use the same sentinel representation as their readers?

For the player: changing a character's appearance reconnects its procedural
controllers to that character's bone storage. The code expects a valid primary
owner for this operation. A missing secondary owner skips updating that link;
it does not directly clear the old cached link. This is a code finding, not an
observed gameplay crash or proof that an invalid state occurs during play.

nonzero Decode(resourceEntry94), then stores incoming EDX as a DWORD at rig68
and calls the full-reset rebinder 3E3D70. It does not independently bound the

the primary-owner refresh is mandatory before any secondary skip/reset exit.

skips the owner/core refresh. Normal completion requires valid table/index/active

## Secondary sentinel, cached links and its actual writer

After normal valid primary processing, the full DWORD6C==FFFFFFFF branch skips
the secondary74/7C refresh in both bodies. There are no direct clears of those
fields on that skip path. Indirect effects and aliasing through downstream calls
are not proved absent. The full-reset body then calls 3E3C30; the link-only body
3E3CA0 does not call that reset in its complete local CFG.

When the full-DWORD skip is false, the reader takes WORD6C and sign-extends it.
A low WORDFFFF or inactive indexed record selects Encode(0) but still calls
421D20. Thus 0000FFFF and FFFFFFFF have different branches. A secondary nullable
boundary presumes normal valid primary processing and the relevant original
objects/state; it is not an independent naturally reachable fault observation.

The supplied secondary producer at 4216D3/4216DB stores MOVSX(WORD firstArgument0)
as the full DWORD rig6C before calling the link-only refresher. This writer maps
WORDFFFF to FFFFFFFF, so it cannot produce the distinct 0000FFFF representation
under those premises. The predicates agree for this producer's full signed16
domain. The exhaustive 65,536 representation calculation is Python fixed-width
arithmetic, not 65,536 native/emulated/live tests. Preserve the counterrepresentation
to explain the guards without inventing a shipped-game bad state or universal
all-writer invariant.
