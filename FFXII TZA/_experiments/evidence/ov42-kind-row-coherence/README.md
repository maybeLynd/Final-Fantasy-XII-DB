## Exact conditional result

The classifier computes the **full unsigned 32-bit** quotient:

`q = floor(((low32(row) - low32(lookup base)) mod 2^32) / u16(second context+8))`

The divisor must be positive. Two separate descriptor loads supply the lookup key and divisor. Normal ABI and readable, stable, nonaliasing state are premises; opaque helper effects are not inferred from their names.

`ADD EAX,-0x94`, unsigned `CMP EAX,0x7F` and the original selector tables make the kind-publishing path write **kind 4 exactly when full q is 208..225**. The classifier never narrows q to a WORD before that guard. This is a bounded source/data proof of the needed kind-4 band, not a repeated authored-name census.

The queue writer uses its own quotient's low 16 bits before sentinel comparison/remap. Therefore:

**If that queue dispatch still uses this published kind 4 and the queue quotient equals the classifier quotient, the queued WORD is 208..225 and the queue DWORD is 0..17. IDs 511..534 are excluded under those explicit premises.**

Equal row low32, equal lookup-base low32 and equal positive divisors suffice. Equal quotients alone is the weaker sufficient premise; pointer identity is not necessary. Neither equality is established for normal callers by this package.

Two mathematical supplied-state countermodels illustrate the limits, without executing original code: classifier q=208/kind4 and a later queue q=511 gives queue303; q=65744 is classified as kind7 despite its low16 value208, which the queue arithmetic would remap to0. Do not use low16 in the classifier or turn the conditional invariant into a natural impossibility claim.

On the classifier's kind-publishing normal-return path, `32FC30`'s return is not tested before `32ED70`; the latter call kills RAX and a context load overwrites it. This is caller-side return-use evidence, not proof of native request/slot effects, successful preparation, presentation or scheduling.
