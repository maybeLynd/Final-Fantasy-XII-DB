# Research provenance — what `Database/Tools/` holds, and what git never knew about it

**Tool:** `Database/Tools/analysis-kit/gfz-scripts/tools_provenance.py` ·
**Data:** [`RESEARCH-PROVENANCE.tsv`](RESEARCH-PROVENANCE.tsv)

Charter §38 lists *"locate all existing research tools and historical work, import with
provenance"* as a first action, and it has been open since the program began.
`research_import_gap.py` answers it for `Collaboration/` prose — that measurement is `ED-1`.
**Nothing answered it for `Database/Tools/` itself.**

## 1. The corpus, and why it is not a tidiness problem

**94 files, 1,036,319 bytes, all text, none of them ever added to git.**

| kind | files | bytes | what it is |
|---|---:|---:|---|
| `TOOL` | **32** | 95,890 | the Ghidra headless runner and its Java scripts, plus three historical Python builders |
| `EVIDENCE` | **20** | 517,317 | dumps those tools produced against the GM160 checkpoint |
| `HANDOFF` | **42** | 423,112 | prior sessions' prose, seals and manifests |

`work/`, `parent/` and `radare2/` are gitignored **on purpose** — scratch, an 82 MB GZF and a
third-party distribution — and are not in scope here. These 94 are not ignored by any rule. They
were simply never staged.

> ### The database cites tools the repository does not contain
>
> **14 of the 15 files any document names are `TOOL` files**, and the citations are load-bearing:
>
> - [`COVERAGE.md`](COVERAGE.md) says its classified-coverage figure is *"machine-verifiable,
>   regenerated by `ReportV121Coverage.java`"*.
> - The mission prompt's non-negotiables say *"update `GfzEnv.ps1` after every certified
>   checkpoint"*, and [`AUDIT-LOG.md`](AUDIT-LOG.md) treats `GfzEnv.ps1` as **the authority on
>   which parent is certified** — quoting its lineage block hash for hash.
> - `Pack-GfzCheckpoint.ps1`, `Invoke-GfzHeadless.ps1`, `Import-GfzParent.ps1` and
>   `Verify-GfzCheckpoint.ps1` are the four steps of the checkpoint discipline the same
>   non-negotiables mandate.
>
> **A clone of this repository could not run any of them, and could not check the lineage claim
> against the file that makes it.** That is a provenance hole, not an untidy directory.

**All 94 are now tracked.** The seals and handoffs are tracked *as history*, not as current truth:
they are prior sessions' claims about the binary, and the standing order is unchanged —
**binary > fresh derivation > prior annotation.**

## 2. What the corpus names that no document does

`gap` is **function entries a file names that no database document cites**. Only 8-hex tokens that
are real entries in `functions.tsv` are counted; a coverage dump is full of eight-hex fields that
are sizes and offsets, and those are not addresses.

| | |
|---|---:|
| distinct function entries named across the corpus | **1,207** |
| …cited by no document | **848** (70.3 % of 1,207) |

**That 70 % is by construction, and reading it as a scandal would be wrong.** The largest files are
`DumpUnresolved*` output — `NEIGHBORHOODS.tsv` (1,037 entries, 795 uncited) and
`MECHANISM_FEATURES.tsv` / `STRUCTURE.tsv` (861 each). They exist *to* enumerate what nothing had
classified, plus each one's callers and callees as context. A dump of the unclassified naming the
unwritten-about is the dump working.

**The number that means something is the worklist itself.**

## 3. The residual worklist, and a document citing a file that changed under it

`evidence/GM160_CURRENT160_ADDRS.txt` is 160 addresses, one per line — the unresolved-function
worklist of the GM160 checkpoint. [`the-unresolved-158.md`](../99-Unresolved-Residual/the-unresolved-158.md)
documents that population and, at its §5, names its canonical list as
`Database/Tools/work/verify/residual_addrs.txt`, *"(158 entries, one per line)"*.

**That file now holds 139.** `work/` is gitignored, so the list is mutable, unversioned, and has
been regenerated twice since the document quoted it.

Three snapshots of the same population survive, and they are **strictly nested**:

| file | entries | written | tracked? |
|---|---:|---|---|
| `evidence/GM160_CURRENT160_ADDRS.txt` | **160** | 2026-09-02 00:06 | **now yes** |
| `work/verify/residual_addrs.txt.GN158` | 158 | 2026-09-02 20:47 | no — gitignored |
| `work/verify/residual_addrs.txt` | **139** | 2026-09-03 19:44 | no — gitignored |

`139 ⊂ 158 ⊂ 160`, verified as sets, no element outside the chain.

> ### The undocumented remainder is identical in all three: exactly the same 112
>
> Cross the three lists against every address any document cites, and the uncited sets are **not
> merely the same size — they are the same set.**
>
> ```
> uncited(160) == uncited(158) == uncited(139)      112 functions
> ```
>
> **So the whole of the 160 → 139 shrink came from functions the database had already written
> about.** All 21 that left the worklist are cited, and they are one recognisable cluster: the
> glyph-run painter, the icon drawers, the coloured-rectangle drawer — `001E8580`, `002AAE40`,
> `002B8EE0`, `002BCB00`, `003649A0` and the rest, every one of them documented in
> `99-Unresolved-Residual/Glyph-Run-Rendering/` and its siblings before a classifier reached them.
>
> **Documentation led classification, and the residual count followed it.** The corollary is the
> useful half: **the 112 will not shrink on their own.** They have survived three classification
> passes untouched, and nothing about them will change until somebody reads one.

**The 112 are all authored code.** None is generated, none is an EH funclet, and **all 112 have no
owner** — they are the `99-Unresolved-Residual` frontier exactly, with the largest at 2,387 B
(`0028BB50`), 1,914 B (`00565E00`) and 1,835 B (`00275570`). `DT-1`.

## 4. What this page does not claim

- **That any of the 94 files is correct.** A GM160 evidence dump is a prior session's claim about
  the binary, exactly like a GFZ annotation. A high `gap` says *"this file names functions nobody
  has written about"* — never *"import these findings"*. They must still be read from the binary.
- **That `gap` measures absorption.** A handoff can be fully absorbed and still name functions no
  document cites; a document can cite an address in passing having absorbed nothing. It is an
  attention proxy over function entries and nothing more.
- **That tracking these files imports them.** Charter §38 asks for *locate* **and** *import with
  provenance*. This page and the commit beside it do the first, and make the second measurable and
  re-runnable. **`ED-1` and `DT-1` are what remains.**
- **That the three worklists describe three different truths.** They describe **one program state
  drifting** — 14 minutes and a day apart — which is what an unversioned evidence file does. The
  document that cited one was not wrong when it was written.
