# UQ-107, the +0x0C clause: what bits 12..31 of the action row's flag dword do (2026-09-27)

Static. Authority image FFXII_TZA.exe (base 0x120000). Row = 60-byte record of the action table at
registry slot `02EBF138`. Every address below is an instruction start taken from a capstone dump
(`dumpfn.py`) or from `y1p_all.txt`.

**Data.** `D:/FFXII_TZA_extract/ps2data/image/ff12/test_battle/us/binaryfile/battle_pack.bin`,
directory `+0x3C` -> `st2e`, `{count 543, stride 60}` (`uq107_rows.py` / `uq107_rows2.py`, a read-only
copy of FABLE's `gg3-scratch/subagent-rows5/scratch_C/uq107_bits.py`). The control is the page's
own profile of `+0x0C`. This dump prints `rows 543 low byte 243 81 69 44 word 99 78`, and the page
gives low byte 140 x 243, 136 x 81, 76 x 69, 0 x 44 and the word 17036 x 99, 9612 x 78, so the two
agree exactly. Names come from `recipe-users.tsv`, keyed by row index. The examples below avoid
rows 128-142, whose `+0x34` name word differs from the row index.

**Reader population.** The inputs were FABLE's 60 provenance-verified `+0x0C` reads
(`uq107_sites.txt`) and `uq107_bits.py`, which classifies them. I added a sweep (`uq107_sweep.py`)
of every `test/and/or/cmp/bt` on `[reg+0xC..0xF]`, plus every `bt reg, 12..31`, in the 129
functions that reference `02EBF138`. I also swept the hop callees in `action-row-reader-hops.tsv`
(`00305640`, `0030A370`, `0030EF20`, `0031A990`, `003216E0`). The sweep found 49 hits outside the
60 known sites. Their register sources are the unit flag word `[unit+0]`, the evaluation-context
word `[r8+8]` or a status word. None of them is a row `+0x0C` read. The bt hits in `0030D160`
(`0030D3B1`, `0030D3E3`) are the known `0030D3AE` load.
**Bound:** the census covers the row pointer's provenance within two hops of the functions that
reference the slot. It does not cover a row copied into another record.

`00322BD5` (in `00322A80`), which was unclassified, is `mov eax,[r15+0xC]` followed by `test al,0x40`
(`00322BD9`) and `test al,0x20` (`00322BED`). It tests **bits 6 and 5**, which are outside 12..31.

## What the pages say that the bytes contradict

1. **`04-Actor-Entity/Battle-Unit/the-battle-unit-field-map.md`, `00312170` paragraph**: "bit 8 set
   unless `[+0xC] & 0x2000`, bit 9 unless `& 0x4000`". The polarity is inverted. `0031221C`
   `mov eax,edx` / `0031221E and eax,0x2000` / `00312223 cmove ecx,ebx` keeps the `bts 8` result only
   when the AND is non-zero, and the same holds at `0031222C`/`00312232` for bit 9. So bit 8 is set
   **iff** bit 13 is set, and bit 9 **iff** bit 14 is set.
2. **`the-action-definition-row.md` line 183 (2026-09-18 narrowing)** says of `0031A990`: "bit 12
   and bit 24 … (`bt 0xc`, `bt 0x18`, together setting `[rdx] = 3`)". In the bytes, bit 12 jumps
   to `0031AA13` (shape 5 or 0) and only bit 24 writes 3 (`0031A9AC`). The sibling page
   [how an action gathers its targets](../../../07-Combat-Action/how-an-action-gathers-its-targets.md) §5
   is correct.
3. **The same line** says bit 19 gives "reason `0x8000221B`". `0x8000221B` is the status mask
   passed in `edx` to `0030E9C0` (`002FFE65`, `002FFE6A`, `002FFE6F`), not a return reason.
4. **The same line** lists the immediates `0x10000000` and `0x20000000` among those that "are not
   the action row's". Both are read on the provenance-verified row pointer `[rbp+0xC]` in `0031EB20`
   (`0031F000`, `0031F0EF`, `0031F157`). The 2026-09-19 correction re-placed only `0x2`,
   `0x200000` and `0x3000000`.
5. **The same line** cites `002F868F` as "`shr 0xd`" and `002F849A` as "`shr 0x1b`". Those two
   addresses are the `and eax, 1` instructions; the shifts are at `002F868C` and `002F8497`.
6. **Field-map row `+0x0C`**: it says "the other bits are read by the two gates, not yet decoded"
   and names three readers. The readers are the ones tabulated above, and the meanings are now read.
7. **Gaps, not contradictions.** The [result record](../../../07-Combat-Action/Result-Record/the-result-record-field-map.md)
   `+0x04` row lists kinds 0-6, 9, `0xA` and `0xB`, but `00390AB0` and `00390F20` also write **7**
   (`00390EF2`, `003910A5`) and `00390AB0` writes **8** (`00390E35`). That page's map also has no
   `+0x10` row, and `00390E42` writes result `+0x10` with a unit pointer.
8. **Input note, not a page.** FABLE's `uq107_bit5_notes.md` says "bit 13 set -> the function
   returns 0" for `002F8410`. It omits the gate: that test runs only under layer id 54
   (`002F8627`/`002F862D`).
