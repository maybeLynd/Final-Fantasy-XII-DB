# OV-16, the motion route: which functions `00268EA0` files, and whether any of them waits (research helper for FABLE, 2026-09-30)

A research record FABLE commissioned, reviewed and publishes (drafted by a read-only helper). It covers the static question that OV-16's status cell and
`../fable-astra-live-facts-0930/ov16_static.md` leave open: *does any function that the motion setter `00268EA0` starts
contain a waited request (`REQSW` / `REQEW`)?* Nothing here touches the board or a tracked file. FABLE reviews it and
publishes it.

The scripts are run from this folder with `python -B <script>.py`. Each exits 1 if a control fails. They were run on
2026-09-30 in the main tree; HEAD was `2e88eceef` when this was written.

## 1. What `00268EA0` files (static, read in the bytes)

**A label correction first.** `00268EA0` does not choose a motion. It files the actor's **`talkhold`** and
**`talkterm`** functions. The functions it starts are footer slots 16 and 17, and ORACLE's RC-12 Part B names those
slots from the raw footers (`../rc12-footer-channels-runstate-0930/README.md`, 1,777 US actors each). This census
checks the same thing again as control C3: 15,934 of 15,934 slot-16 words name `talkhold`, and 15,934 of 15,934 slot-17
words name `talkterm`.

`ov16m_image.out` Part A, confirming FABLE's reading of the bytes:
- `r14 = 02098E10 + actor[+0x15] * 0x288` (`00268EBE`–`00268ED6`) is the actor-manager slot, and `rbx = [r14]`
  (`00268F09` / `00268F50`) is its image base.
- The resolve call `0020E600` (`ImageAddress_ResolveRuntimePointer`) is `mov eax, ecx; add rax, [01F83530]; ret`. So it
  returns the dword argument plus the universal relative-reference base (`CONTRACT-encoded-id-space-and-class-registry.md`
  §6, E8). Its argument is `[[actor+0x40]+0x18]`, which is the actor directory entry's `sepaOff`
  (`section-000-bytecode.md` §4, BW-5). The caller keeps only the low dword (`00268F14` / `00268F5B` `mov ecx, eax`) and
  indexes `rbx` with it. So `rbx + off` is the actor's **`tFuncFooter {u16 count; u16 special[18]}`**. `special[k]` sits
  at `+2 + 2k` and is a **function index in the actor's own function table** (entry `+0x10`,
  `{u32 nameOff, u32 offsetWithinScript}`).
- The two reads:

  | call | override word | bound | footer word | slot |
  |---|---|---|---|---|
  | `00268F56` | `+0xE8` (`00268F3F`) | `0x10` | `+0x22` (`00268F68`) | k = 16, `talkhold` |
  | `00268F0F` | `+0xEA` (`00268EF8`) | `0x11` | `+0x24` (`00268F21`) | k = 17, `talkterm` |

  The override word is `0xFFFF` for "not overridden". This agrees with the `0xC8 + 2k` override array (FI-1 N2–N4).
- The gates: record `+0x1C` bit 16 (`0x10000`, `00268F2B`) gates `talkhold`, and bit 17 (`0x20000`, `00268EDC`) gates
  `talkterm`. `+0x18 == 1` forces id 0 and skips both submits (`00268FD7`, `00269011`).
- The submits go through `003DBBE0` → `003DBBF0`:
  - **`talkhold`**: 6th argument (kind) `ebx` = 5 (`00268FB3`, stored `00268FDD`); 5th argument 1 (`00268FE7`); channel
    6, or 4 when `+3 & 0x1F` is 7 (`00268FBC`–`00268FD1`).
  - **`talkterm`**: kind 4 (`00269017`); 5th argument 2 (`00269025`); channel 5, or 3 for sequence 7
    (`00268FFB`–`0026900C`). This matches RC-13's channel table.
- Before submitting, it clears the old entries: `002626C0` (kind 4 on channel 3/5) at `00268FA6` and `00262740` (kind 5
  on channel 4/6) at `00268FAE`.

**Kind 4 and kind 5 come only from `00268EA0`** (Part B). The thunk `003DBBE0` has four raw call sites, and `003DBBF0`
has none besides the thunk's `jmp`:
- `00268B10` passes `r15d`, zeroed at `00268C4A`;
- `00268D10` passes `ebx`, which is 1 or `ebp` = 0 (`00268D16`, `00268D7C`, `00268DB3`);
- `00268EA0` passes 5 and 4.

So "kind-4/5 entry" means exactly **a `talkterm` / `talkhold` entry filed by `00268EA0`**.

**The kind-4/5 clears have two raw callers each** (the rel32 index):
- `00268EA0` itself (`00268FA6` / `00268FAE`);
- `0025D5E0` (`0025D60C` / `0025D61A`). `0025D5E0(record, index)` clears `+0x1C` bit `index`. For index 17 it calls
  `002626C0`, and for index 16 it clears `+0x0B` bit 2 and calls `00262740`. It is the tail of the verb
  **`reqdisable`** (`0x02B`, handler `003558F0` → `jmp 0025D5E0` at `0035590B`). Its other callers are `00238BF0`,
  `00355830` and `00355A00` (fieldsign).

The ov16_static claim *"the only code that clears them is the motion setter itself"* is therefore short by
**`reqdisable(16)` / `reqdisable(17)`**.

**Who re-runs `00268EA0`.** There are 14 raw sites in 11 functions:
- `0025AD10`, `0025AE00`;
- the interpreter's `REQCHG` handler (`0026160B`, slots `0x10`–`0x11`, when the target's `+0x0B` bit 3 is set);
- the record initialiser `00266530` (×2);
- `00267CC0` (×4), `00268D10` (the engine talk), `00269FE0` (×2), `0026CE60`;
- the leaf `0026B4A0`, the `jmp` at `0026B4BA`. `0026B4A0` is `+0x1C |= 1 << dl`, then a tail into `00268EA0` when
  `+0x0B` bit 3 is set. It is the tail of **`reqenable`** (`0x02A`, handler `00355540` → `jmp 0026B4A0` at `0035555B`),
  of `setupbattle`'s begin (`00351F40`) and of `fieldsign` (`00355A00`).

Each re-run first removes the actor's existing `talkhold` / `talkterm` entries, then files new ones.

## 2. Who writes the override words `+0xE8` / `+0xEA` (static)

This is a raw store census (`ov16m_image.out` Part C). It covers every `.pdata` chain root and every uncovered `.text`
run: 47,110 streams and 2,104,075 instructions. It lists every written memory operand whose byte range meets
`0xC8`–`0xF8`, whatever the base, and whether it is fixed, indexed or a `rep stos` / `movs`. That gives 5,365 rows in the
window. 620 of them meet `+0xE8`–`+0xEB` or are indexed stores with a displacement of at most `0xEA`; all 620 are in the
TSV.

Controls PASS:
- the indexed writer `0025AFA1`;
- the fixed writer `0025AD34` (`+0xF6`);
- the initialiser's string store `002668B0`.

The functions the three actor-record census tables prove to take a record (331 functions) contribute exactly two rows:
- `00266530` `002668B0`: `rep stosw`, `rdi = +0xC8`, 18 words. This is the initialiser's `0xFFFF` fill (FI-1).
- `0025AE00` `0025AEC2`: `mov word [rax + rdi*2 + 0xc8], r15w`, with the slot `edi` in {0, 7, `r13` = 10, `edx + 0xC` = 14}
  (`0025AE8C`–`0025AE9D`; RC-12).

In the script-VM / actor band, there is also:
- **`0025AF60` `0025AFA1`** `mov word [rax + rbx*2 + 0xc8], di`, which refuses a slot above `0x11`. Its two raw callers
  are:
  - `0025AD10` (`0025AD7E`), with slots 0, 7, 10 and 14 only (`0025AD4D`–`0025AD72`: list 0 → 0, 1 → 7, 2 → 10,
    3 → none, 4 → 14);
  - the **`REQCHG`** handler (`002615EB`), whose slot is the popped script operand.
- Eight fixed-displacement rows at `+0xE8`, all on other objects (read by hand):
  - `002509D0` and the leaf at `00251F00`: the `020927F0` transition / fade object;
  - `00258350`: a pointer store at `+0xE8`;
  - `002628B0` and `0026C8C0`: the `02098E10` manager slot (`+0x10` live bit, `+0x1FC`);
  - `003DA8A0` / `003DA9F0`: the `0x130`-stride movement-body pool.

  None of these stores a u16 on an actor record.

**So statically the only writer of slots 16 / 17 (`+0xE8` / `+0xEA`) apart from the `0xFFFF` fill is the script opcode
`REQCHG` (`0x34`) with slot 16 / 17.** A store the sweep cannot see is one made through a computed base with no
displacement, or through a `memcpy` of a whole record. Those are not excluded.

## 4. Verdict

**Possible, not impossible.** Exactly one shipped function that `00268EA0` files contains a waited request:
`asp_a03` `ラバナ_通常_NPC01::talkterm`, an `REQEW` on channel 1 of `ラバナ_通常_NPC01_TRAP::re_on`, filed as kind 4 on
channel 5 (channel 3 for a sequence-7 record). It appears in all 9 language copies. None of the other 31,859 footer
functions wait, and neither do any of the 450 `REQCHG` override functions.

What stays open, kept separate:
- **Static inference, not read here:** that this actor's record gets `+0x1C` bits 16/17 at birth. The initialiser sets
  them for sequences 5, 6 and 7 (`actor-storage-record-flags1c-initial-values.tsv`, `0x00030004` for 6). The record's
  sequence is the carve-loop class `k` (`the-record-behind-every-actor.md`, EH-1, `00267AFA`–`00267B13`). That `k`
  equals the directory `scriptType` (6 here) through the header `+0x14` per-type counts is the one link not read in the
  bytes. Even without it, `attack_02`'s `reqenable(17)` sets bit 17 explicitly.
- **The live fact (the interleaving) for OV-16's motion route**, now pinned to one actor: in play, does `00268EA0`
  re-run, or does `reqdisable(17)` / `reqenable(17)` fire, while this `talkterm` is parked in its `REQEW` on the TRAP
  actor's `re_on`? And does `talkterm` then re-run to the same continuation offset (`+0x35`, right after the `REQEW` at
  function offset `0x34`) before the old end notification is consumed? The candidate triggers are:
  - `NPC01::attack_01` / `attack_02` (the reqdisable / reqenable pair);
  - any other `00268EA0` caller in §1, for example the engine talk `00268D10`, the `REQCHG` handler, and the
    free-target-type setters `00267CC0` / `00269FE0`.
- **Corrections for FABLE's record `ov16_static.md`:**
  1. "motion setter" and "motion entries" should read **`talkhold` / `talkterm` filer** and **`talkhold` (kind 5) /
     `talkterm` (kind 4) entries**;
  2. "the only code that clears them is the motion setter itself" misses **`0025D5E0`**, which is `reqdisable`'s tail;
  3. OV-16's status sentence "the motion route's static question ... is still open" can now be stated as **one function
     in one zone (`asp_a03`, ×9 language copies)**.
