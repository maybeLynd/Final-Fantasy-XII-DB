# Consumer check: the suspend/restore copy loop's census rows re-attributed (SWE2-STRUCT, 2026-10-03)

This answers `OPUS-REQ-STRUCT-SUSPEND-COPY-CENSUS-ROWS-1001` under package `SWE2-STRUCT-SUSPCOPY-CENSUS-1003`
(work done by a Claude session standing in for the Devin SWE2-STRUCT session while Devin was rate-limited).

The restore `0030EDA0` and the snapshot `0030EFF0` copy `[unit+0x6B0, unit+0xBA0)`. The copy is a loop of nine passes of
eight 16-byte moves: `mov edx, 9` (`0030EDB1` / `0030F051`), pointer step `lea ..., [... + 0x80]` (`0030EDB6`,
`0030EDC0` / `0030F056`, `0030F060`), `sub rdx, 1; jne` (`0030EE03`-`0030EE07` / `0030F0A3`-`0030F0A7`). It is followed by a
seven-move tail that runs with the pointer at `+0x6B0 + 9*0x80 = +0xB30`. The census follows pass 0 only. It filed the
tail at the first `lea`'s `+0x730`. OPUS named two of the tail rows; all seven tail moves of each function carry the
same error.

- **Corrects:** `04-Actor-Entity/Battle-Unit/battle-unit-accesses.tsv`. There, the 14 tail rows (`0030EE13`-`0030EE44`
  writes, `0030F0A9`-`0030F0DD` reads) are re-filed from `+0x730..+0x790` to `+0xB30..+0xB90`. The 18 loop-body and
  loop-carried `lea` rows are annotated "loop pass 0 of 9" with the offsets passes 1-8 reach, so the loop is marked as
  unfollowed rather than silently credited to pass 0.
- **affected:** the BattleUnit census, its two projected child censuses (BattleTargetBuffer, BattleTargetResultEntry) and the type store's BattleUnit rows - all four are TSVs touched by this publish, listed by path here:
  `04-Actor-Entity/Battle-Unit/battle-unit-accesses.tsv`, `04-Actor-Entity/Battle-Unit/battle-target-buffer-accesses.tsv`,
  `04-Actor-Entity/Battle-Unit/battle-target-result-entry-accesses.tsv`, `_types/fields.tsv`.
- **Regression:** `loop_attribution_check.py --check` (this directory). It decodes the loop shape and every tail
  site from the shipping image, then fails on any census row it would still change or drop. Run at e69188d39:
  FAILS 0 ([`loop_attribution_check.out`](loop_attribution_check.out)). Sensitivity: the same script, pointed at
  the census as it stood at that sha, reports 32 rows to change and 4 to drop (FAILS 2).
