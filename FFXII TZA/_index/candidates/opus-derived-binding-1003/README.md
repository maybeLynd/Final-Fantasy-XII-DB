# Derived surfaces bound to their commit (OPUS, 2026-10-03)

*The user's root-cause directive (FFXII Return Package — Root-Cause Correction and Continuation Directive), items 1, 2 and
7: a derived surface claimed `CURRENT` while its authoritative input had moved; a return package claimed more patches
than it held; nothing validated a checkpoint's current surfaces against their sources.*

## Item 1 — stale `PROGRESS.md` kept `CURRENT` (OPUS)

**Visible symptom.** At HEAD `e1b42c48b`, `PROGRESS.md` reads `**freshness:** `CURRENT`` and "52 MET of 52 systems"
(generated 2026-10-03T07:11:25Z from `39bcb329b`), while `L2-VERDICTS.md` in the same tree parses to 36 MET of 52
(`78b17b620` moved four systems at 07:27Z; AUDIT-SEM's later re-scores moved more). The return ZIP shipped that copy.
Receipt: [`checkpoint.HEAD-before.out`](checkpoint.HEAD-before.out) — C2, C3 and C4 FAIL.

**Root cause — four mechanisms, each necessary:**

1. *Generation-time assertion in a committed file.* `CURRENT` was written by the generator at build time into a tracked
   file that outlives its inputs. The generation store (`generation.py`) binds a generation to its input bytes, but only
   inside the ignored store; the committed copy carried no binding, so nothing could tell a later reader it was stale.
2. *Publication did not follow dependencies.* `L2-VERDICTS.md` is a registered required input of the reporter, yet its
   publish (`78b17b620`) neither regenerated nor invalidated `PROGRESS.md`. `publish_paths.sh` only touched a `.dirty`
   mark for the watchdog.
3. *Regeneration landed only in the worktree.* The watchdog regenerated `PROGRESS.md` (08:31Z read 48/52), but derived
   outputs were committed only when SWE2-DATA happened to publish them — five times in two days.
4. *Every build aborted while the fleet worked.* The reporter's mid-build coherence check fingerprinted the board
   revision, and the board is rewritten every few seconds. Measured 08:45Z: 3 of 3 generations aborted `INCOMPLETE`, and
   the only input that moved in 15 s was `TEAM.json`. The build also read the board three times (`parse_board`, batch-K
   carrier owners, `transfer_audit`), so a build that did finish could mix board states.

Not causes: dependency registration (`L2-VERDICTS.md` was registered) and fingerprint coverage (complete bytes).

**Shared mechanism repaired:**

- [`derived_binding.py`](../../../../Tools/analysis-kit/gfz-scripts/derived_binding.py) (new, shared): a generator that
  publishes into the tree writes `GENERATION-BINDING.json` beside its outputs — every non-volatile repository input it
  consumed (EOL-normalised sha256 of the exact bytes), the volatile/derived inputs as *as-of*, the outputs' hashes, the
  supported regeneration command and how the outputs say STALE. `state()` evaluates a binding against the worktree, a
  commit or a private index: `CURRENT`, declared `STALE`, `FALSE-CURRENT` (forbidden) or `INCOHERENT`.
- `publish_paths.sh` (every lane's publish) runs `derived_binding.py gate` on its private index before the tree is
  written: a surface whose bound inputs the commit moves is regenerated by its supported command and **included in the
  same commit** when it binds to that tree; otherwise the committed outputs are relabelled **`STALE`** naming the moved
  inputs. A source edit is never blocked on a derived surface; a derived surface never claims `CURRENT` over moved
  inputs. The repository index for gate-staged paths is refreshed from HEAD. The edit was one atomic file replace (the
  script is shared and was in use).
- `progress_report.py`: writes the binding after its verified copy-out (outputs outside the repository — the test suite —
  get none); takes **one board snapshot per build** (every board reader and the fingerprint use it; the store binds those
  exact bytes as volatile; live `check` still fingerprints the live board); and **serialises builds** with a lock file that
  reaps a dead or 15-minute holder (two concurrent builds had failed mid-copy with "the live set may be mixed").

**Current instance repaired.** The publish carrying this record commits `PROGRESS.md` and its route files with their
binding through the gate itself: `CURRENT` if every bound input in the commit equals what the generation read, otherwise
committed `STALE` naming the input (at the time of writing SWE2-AUDIT-SEM held uncommitted `L2-VERDICTS.md` re-scores in
the worktree; their own publish then regenerates `PROGRESS.md` inside that commit).

**Regression proof:**

- [`derived_binding.selftest.out`](derived_binding.selftest.out) (11 cases, 0 failures), in a temporary repository: a valid
  generation is CURRENT; a commit that moves the verdict input without the gate makes it FALSE-CURRENT and the checkpoint
  check fails; a publish through the gate regenerates and includes the outputs, which reflect the changed verdict and are
  CURRENT; with the generator broken the gate still publishes the source edit and commits the outputs labelled STALE
  (text and JSON); a hand-edited output is INCOHERENT; the volatile board is as-of, never bound.
- [`test_progress_report.out`](test_progress_report.out): FAILS 0 (baseline before this change: FAILS 1, T4 failing on
  live board writes). New T4b/T4c: the fingerprint reads the build's one board snapshot; with none it reads the live board.

**Other inputs reviewed for the same hole.** The reporter's 13 required and 2 optional inputs, its three instruments,
itself and `progress.config.json` are all bound (17 bound inputs in the live binding); the board is as-of by design; the
document-tree preimage is recorded as-of (the live `check` keeps it strict). `knowledge.sqlite` (item 3) has its own
fail-closed dependency check (C6 below) and is not a committed surface. The dashboard serves from its generation store
and is not committed.

**A second guard had to learn the same distinction.** The first attempt to publish this package (OPUS-PUB-CONSOLIDATED-1003Q)
was refused by `check_stale_preimage.py`: regenerated `snapshot.json` "would remove 181 of 290 lines 765ec764d added".
A generator replaces its outputs whole on every generation, so every regeneration looks like a revert of the previous
one. `check_stale_preimage.py` now exempts exactly the outputs of a `GENERATION-BINDING.json` published in the same
batch whose worktree bytes equal what that binding records (a note is printed, not a finding); every other path keeps the
revert rule. Applied as one atomic file replace (shared gate); its own self-test still passes (7 cases).

## Item 2 — return-package provenance overclaimed (OPUS, built by repos-91 on OPUS's specification)

**Visible symptom.** The earlier return ZIP's report said every listed commit was a format-patch; `240ceade4` and
`e25142cd3` were cited without one.

**Root cause.** OPUS's `build_zip.py` took its patch list from `SHAS.txt` lines starting with a sha; the report was prose
written separately; nothing compared the report's citations and claims with the exported members.

**Shared mechanism.** [`return_package.py`](../../../../Tools/analysis-kit/gfz-scripts/return_package.py): `build` derives
`PROVENANCE.json` (each commit `FORMAT_PATCH`, `FINAL_SNAPSHOT` or `RECEIPT_ONLY`, with the members that carry it) and
`MANIFEST.json` from what it actually wrote, verifies the ZIP before renaming it, and never overwrites. `verify` fails on:
a report citing a commit with no provenance (A), a missing or mis-attributed patch (B), a stray patch (C), a missing or
unknown representation (D), a patch name disagreeing with its `From` line (E), any manifest mismatch (F), a snapshot entry
with no file (G), and report prose claiming stronger completeness than the package holds (R_OVERCLAIM).
Proof: [`return_package.selftest.out`](return_package.selftest.out), 15 cases, 0 failures — including the original defect
end to end (a report citing an unexported commit and claiming "every listed commit is included as a format-patch" is
refused, no ZIP written).

## Item 7 — checkpoint current-state consistency (OPUS)

[`checkpoint_consistency.py`](../../../../Tools/analysis-kit/gfz-scripts/checkpoint_consistency.py) runs against a commit
or the worktree: C1 bindings CURRENT or declared STALE; C2 no `freshness: CURRENT` without a binding; C3 PROGRESS's L2
headline equals the rows of the same tree; C4 every hand-kept count table in `L2-VERDICTS.md` equals a recount of its rows;
C5 `goal_gate.py` agrees (worktree, `--slow`); C6 `knowledge.sqlite` freshness; C7 lifecycle consumers; C8 status residue.
STALE is legal; FAIL is a false current surface. At HEAD `e1b42c48b` before this publish: **FAIL 3**
([`checkpoint.HEAD-before.out`](checkpoint.HEAD-before.out)). New finding: `L2-VERDICTS.md`'s contract-column summary reads
MET 47 / SCOPE-SHORT 3 against rows 52 / 0 — a hand summary that drifted; routed to the file's current editors.

## Limits (OPUS)

The binding binds files in the repository. The document-tree preimage and the board are recorded as-of, so a committed
`PROGRESS.md` is exact for its registers and instruments and as-of for page-box counts and coordination counts; the
live `check` mode remains strict for both. Commits made outside `publish_paths.sh` are not gated; C1-C4 catch them at the
next checkpoint and the next gated publish repairs them.
