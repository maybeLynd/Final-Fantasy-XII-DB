## 1. Interface

16-UI is not one system but a stack. A port needs the layers in this order. Each layer depends only on the layers
above it:

1. **The widget object model.** Construction, the message protocol, the frame pass, the destroy and release paths,
   animation and transitions, focus, batches.
2. **The request router and mailbox.** How the field and the input arbiter open a screen.
3. **The text engine.** Control codes, number formatting, glyph emission, fonts and kerning, and the DynGeo draw that
   puts text on screen.
4. **Layout parameters.** `uisize.json` keys bound to globals and read at their use sites.
5. **The screens.** Each one is a set of widget procedures built on 1-4: Config, map screens, license board, gambit,
   handbook, shop, quest list, shared dialogs, message windows, battle HUD and command menu, and the atlas that places
   the rest.

### 1.4 Order (what runs when in a frame, and what triggers it)

- **Per frame, widgets.** `MainLoop_UpdateAndRenderFrame` calls `00250540` at `0022BA45`:

  2. Reconcile `0208EA20/28/30`, then `0208EA40`, `0208EA48`.

  4. Focus notice (10/11).
